Project Overview: Introduction

Secure Distributed Architecture

Traditional single-node systems execute motor sweeps, measurements, and rendering in a sequential loop. This blocks execution during sensor wait times and results in scanning blind spots. We resolve this by partitioning tasks across two main nodes:

  • Node 1 (Sensor Node): Governed by FreeRTOS on an ATmega328P to schedule three servos and ultrasonic sensors in a round-robin loop, encrypting telemetry data into secure frames.
  • Node 2 (Edge Node): A multi-threaded C++20 backend running on an NVIDIA Jetson Nano that handles raw serial ingestion, frame decryption, spatial association, and real-time GPU rendering.

Moving Target Indication

Rather than plotting static, isolated point blips, our MTI engine analyzes target movements across consecutive sweeps. The system tracks coordinates, applies a Nearest-Neighbor Euclidean association filter, and estimates velocity vectors to predict headings:

$$\vec{d}_i = (x_{t,i} - x_{t-1,i},\, y_{t,i} - y_{t-1,i})$$
$$v_i = \|\vec{d}_i\| / \Delta t$$

Computed displacements are mapped to speed and heading parameters, which are rendered as glowing, directional velocity arrows on a Plan Position Indicator (PPI) screen.

Problem Definition

1. Processing and Timing Bottlenecks

Sequential execution of motor control, polling, and graphics introduces CPU blocking during acoustic echo windows ($\approx 5.8\text{ ms}$ round-trip for 1 meter). This causes sweeping delays and creates angular blind spots where moving targets bypass detection.

2. Communication Link Vulnerability

Standard serial lines lack encryption and parity safeguards. Electromagnetic interference (EMI) from motors causes random bit flips, resulting in phantom coordinates or missed blips. Additionally, unsecure lines are vulnerable to target spoofing or packet injection.

3. Absence of Target Tracking

Basic systems plot only instantaneous distance points without historical association. Without correlating detections across consecutive sweeps, operators cannot derive motion parameters like velocity or heading, making it impossible to analyze target trajectories.

4. Volatile Logging Constraints

Digital storage media on edge nodes can be easily modified, corrupted, or wiped. A malicious actor with local operating system access can alter sweep data. An independent, tamper-evident, and physical logging mechanism is needed for tactical audit trails.

Challenges & Solutions

Hardware & Cryptography

  • Acoustic Crosstalk: Firing multiple ultrasonic sensors simultaneously causes echo signals to interfere, resulting in false range measurements.
    Round-Robin Sequence + 5 ms Settle Delay

    Sensors are triggered sequentially (Main → Left → Right) with a 5 ms delay, allowing echoes to decay before the next channel is polled.

  • 8-bit MCU Constraints: Standard encryption like AES-128 is highly memory-intensive and exceeds the 2 KB SRAM budget on the ATmega328P.
    Lightweight XTEA Block Cipher (ECB Mode)

    We implement XTEA (32 rounds, 128-bit key) in under 20 lines of C. It uses simple bit shifts and additions, avoiding S-boxes and operating in constant time.

Ingestion & Rendering

  • Real-Time Ingestion: Reading continuous, high-baud rate serial telemetry (115200) without dropping packets on a multi-tasking OS like Ubuntu.
    Asymmetric POSIX termios Thread

    A dedicated C++ serial thread bypasses system formatting by setting termios to raw input mode, continuously filling a thread-safe circular sweep buffer.

  • GPU Parallelization: Running Nearest-Neighbor spatial distance association and drawing smooth graphics in real time is computationally heavy.
    Vulkan Compute Shaders for MTI

    The C++ backend offloads target tracking calculations to Vulkan compute shader work groups, parallelizing spatial math directly on the Jetson Nano GPU.

Solutions: Implementation

FreeRTOS Task Pipeline

rawDataQueue = xQueueCreate(5, sizeof(RawData3));
txQueue      = xQueueCreate(5, sizeof(TelemetryFrame));
if (rawDataQueue != NULL && txQueue != NULL) {
  xTaskCreate(TaskUARTDispatch,    "UART",   90,  NULL, 3, NULL);
  xTaskCreate(TaskSecurity,        "Crypto", 160, NULL, 2, NULL);
  xTaskCreate(TaskScanCoordinator, "Scan",   200, NULL, 1, NULL);
}

By decoupling sensor sampling, XTEA encryption, and UART transmission into three separate tasks communicating via FreeRTOS queues, we prevent timing overruns and maintain a deterministic sweep rate.

XTEA Block Cipher

void xtea_encrypt(uint32_t v[2], uint32_t const key[4]) {
  uint32_t v0 = v[0], v1 = v[1], sum = 0;
  uint32_t delta = 0x9E3779B9;
  for (unsigned int i = 0; i < 32; i++) {
    v0 += (((v1 << 4) ^ (v1 >> 5)) + v1) ^ (sum + key[sum & 3]);
    sum += delta;
    v1 += (((v0 << 4) ^ (v0 >> 5)) + v0) ^ (sum + key[(sum>>11) & 3]);
  }
  v[0] = v0; v[1] = v1;
}

XTEA operates as a constant-time 64-bit block cipher with a 128-bit key. It relies on a golden ratio constant ($\delta = 0\text{x}9E3779B9$) for bit diffusion, ensuring cryptographic resistance to side-channel timing leaks.

System Specifications

Hardware Stack

  • Arduino Uno: Governed by FreeRTOS on ATmega328P to schedule polling and serial serialization.
  • MG90S Servos: Three metal-gear micro servos sweeping independent overlapping arcs.
  • HC-SR04 Sensors: Two ultrasonic modules measuring distance for Main and Left channels.
  • HY-SRF05 Sensor: One ultrasonic sensor utilized for the Right channel flank.
  • Jetson Nano: ARM host executing multi-threaded tracking and Vulkan PPI shaders.
  • Thermal Printer: 58mm USB printer processing raster logs via ESC/POS command sequences.

Software Stack

  • Firmware: FreeRTOS task partition with raw serial ISR dispatch on ATmega328P.
  • Backend: Multi-threaded C++20 application managing raw serial ingestion and data processing.
  • Vulkan UI: High-performance graphics pipeline utilizing double-buffered swapchains.
  • Shaders: GLSL compute shader parallel tracking and CRT decay fragment shaders.
  • Simulink: Full-system simulation built programmatically via MATLAB API scripts.
  • Tests: Google Test framework validating protocol parsing and XTEA block decryption.

Telemetry is packaged into a 20-byte fixed-size frame transmitted over UART at 115200 baud. The 16-byte plaintext payload is encrypted using dual-block XTEA. A 16-bit CRC-16 CCITT trailer (poly 0x1021) is calculated over the header and ciphertext, providing a 99.998% error detection probability.

MATLAB/Simulink Validation

Programmatic Simulation Architecture

To validate our architecture prior to physical deployment, we developed a multi-rate Simulink model. This model is constructed programmatically via MATLAB API scripts (build_radar_model.m) to ensure 100% test reproducibility.

Fidelity Cross-Validation: Sim vs Hardware yields a 0.08% vs 0.10% frame drop rate under clean link conditions, proving numerical model equivalence.

  • Scene Generator: Updates target positions at runtime using linear kinematic motion paths.
  • Sensor Block: Replicates FreeRTOS round-robin scheduling, encryption, and frame packing.
  • Channel Model: Simulates physical EMI via additive Gaussian noise and random packet dropouts.
  • Parser Block: Verifies CRC checksums and decrypts dual-block ciphertext arrays.
  • MTI Engine: Performs spatial association and registers velocity coordinate updates.
  • Virtual Printer: Emulates the ESC/POS printing protocol, outputting standard PBM files.

Conclusion

Key Achievements

  • FreeRTOS Scan Coordinator: Eliminates scanning blind spots by decoupling physical sweeps from coordinate transmission.
  • XTEA/CRC-16 Framing: Encrypts UART communications and ensures 99.998% link drop detection in noisy environments.
  • Vulkan Compute Acceleration: Offloads tracking calculations to Maxwell workgroups, maintaining rendering at 60+ FPS.
  • Thermal Audit Logs: Generates permanent, physical scan history trails, mitigating digital record tampering.
  • Simulink Verification: Confirms mathematical models and secure framing algorithms with bit-level system equivalence.

Future Roadmap

  • EEPROM Calibration: Store sensor-servo mounting offsets directly in the Arduino's volatile-safe on-chip EEPROM.
  • Adaptive Scanning: Dynamically scale servo sweep speeds depending on target density and motion vectors.
  • XTEA-CBC Encryption: Implement Cipher Block Chaining to eliminate identical ciphertext blocks inherent to ECB mode.
  • Kalman Filtering: Replace Nearest-Neighbor tracking with an Extended Kalman Filter (EKF) to smoothen coordinate paths.
